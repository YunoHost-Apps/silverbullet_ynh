Le contrôle d'accès est désormais séparé en deux permissions SSO : `main` (l'interface) et `api` (l'API HTTP sous `/.fs`). Les deux exigent toujours la connexion SilverBullet ou un token Bearer : ouvrir l'une aux visiteurs ne contourne pas l'authentification SilverBullet.

Les tokens API se créent depuis le tableau de bord SilverBullet (`/.dashboard` → votre utilisateur → API tokens) et s'utilisent comme `Authorization: Bearer <token>`. `SB_AUTH_TOKEN` dans `custom.env` n'est plus nécessaire (et doit rester désactivé, voir la note précédente).
