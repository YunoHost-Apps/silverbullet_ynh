SilverBullet now creates its admin account and first space automatically at install time, so there is no setup wizard to complete on a new install. The administrator chosen during installation can log in at the app URL with the password given during installation.

If your instance is stuck and the service will not start after this upgrade, check whether `SB_USER` or `SB_AUTH_TOKEN` is set in the app `custom.env`. Since SilverBullet 2.11, an instance that has gone through the setup wizard keeps its accounts in `users.json`, and the server then refuses to boot with:

    this folder contains spaces.json (multi-space config) but SB_USER is set.
    Accounts now live in users.json - unset SB_USER

Remove those two variables and restart the app. The workaround that suggested adding them (see issue #18) applied to the single-space mode used before 2.11: on a current install it either pins the server to that deprecated mode, or — if setup has already run — prevents it from starting.
