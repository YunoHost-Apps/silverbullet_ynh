Access control is now split in two SSO permissions: `main` (the UI) and `api` (the HTTP API under `/.fs`). Both still require SilverBullet's own login or a Bearer token: opening one to visitors does not bypass SilverBullet authentication.

API tokens are created from the SilverBullet dashboard (`/.dashboard` → your user → API tokens) and used as `Authorization: Bearer <token>`. `SB_AUTH_TOKEN` in `custom.env` is no longer needed (and must stay unset, see the previous note).
